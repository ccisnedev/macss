MACSS structures a software project as vertical modules that each own their full stack slice — database, API, UI and infrastructure. A single developer holds complete context: no hand-offs, no layer silos. Every module can be extracted as a microservice without changing its internal architecture. The bet is ownership over specialization.

The four elements

Every MACSS module spans all four layers. macss create <path> scaffolds them instantly.

db Earth

Persistence layer. SQL schemas, DDL scripts, repositories. Managed as Database as Code — no ORMs, no incremental migrations.

api Air

Business logic layer. Use cases, CQRS split: REST for commands, GraphQL for queries. Every operation goes through a typed UseCase.

ui Water

Presentation layer. Controllers, services, views. Adapts to the container — CLI, web or mobile — without touching business logic.

infra Fire

Deployment and operations. CI pipelines, Docker, environment config. The layer that builds, ships and destroys on demand.

CLI commands

macss

Display the banner, version and available commands.

macss create <path>

Scaffold a new MACSS project at <path> — creates code/{db,api,ui,infra} and doc templates.

macss doctor

Verify local installation and asset integrity.

macss upgrade

Download and apply the latest release from GitHub.

macss uninstall

Remove MACSS CLI from the system and clean PATH.

macss version

Print the current CLI version.
