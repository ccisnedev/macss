macss

Modular Architecture for Comprehensive Software Solutions

GitHub → Install CLI →

MACSS is a software architecture methodology. It structures projects as vertical modules where each module owns all four layers: persistence, business logic, presentation, and infrastructure. Three principles govern the approach: modular architecture (explicit boundaries between modules), executable specification (tests and contracts define the system), and closed-loop verification (automated checks validate every change). A single developer maintains full context across all layers. Any module can be extracted as an independent service without modifying its internal structure.

Layers

Every MACSS module is a vertical slice that owns all four layers. The module boundary is explicit and its dependencies on other modules are declared.

db

Persistence. SQL schemas and DDL scripts managed as code. No ORMs, no incremental migrations. The schema is the contract.

api

Business logic. Use cases with typed Input / Output DTOs and a validate() + execute() lifecycle. CQRS: REST for commands, GraphQL for queries.

modular_api →
ui

Presentation. Controllers, services, views. Consumes the API through a transport-agnostic client with the Result pattern. No raw HTTP in the presentation layer.

service_client →
infra

Infrastructure. CI pipelines, containers, environment configuration. Handles build, deployment, and teardown.

Modules

A module groups related use cases from the same business domain — clients, billing, inventory. Each module is a vertical cut across all four layers:

module clients/
├── db/    → DDL scripts, repositories
├── api/   → use cases, endpoints
├── ui/    → service, controller, views
└── infra/ → module-specific config

When a module needs to scale independently, it can be extracted as a separate service. The internal architecture remains unchanged because the boundary is already explicit.

CLI

The macss CLI scaffolds the standard project structure from templates.

PowerShell irm https://macss.ccisne.dev/install.ps1 | iex

Installs to %LOCALAPPDATA%\macss\, adds macss and alias ma to PATH.

Bash curl -fsSL https://macss.ccisne.dev/install.sh | bash

Installs to ~/.macss/, adds macss and alias ma to PATH.

macss create <path>

Scaffold a new project with code/{db,api,ui,infra} and documentation templates.

macss doctor

Verify installation integrity.

macss upgrade

Download and apply the latest release.

macss version

Print the installed version.
